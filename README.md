## Генератор артефактов
---

### Общие сведения
---
Проект предназначен для прохождения на стажировку **Yadro Impulse**. Здесь представлено решение задачи для конвертации некоторых входных файлов в соответствующие выходные файлы (артефакты).

`./input/`
---
* `config.json` -- конфигурационный файл с некоторым набором параметров
* `patched_config.json` -- обновлённый конфиг с новыми и модифицированными данными
* `impulse_test_input.xml` -- XML-файл модели с описанием классов и их агрегациями

`./output/`
---
* `config.xml` -- пример внутренней конфигурации, соответствующий представленной модели
* `meta.json` -- мета-информация о классах и их атрибутах
* `delta.json` -- разница, между содержимым `config.json` и `patched_config.json`
* `res_patched_config` -- применённая дельта к изначальному `config.json`

### Структура
---
* `./input/` -- входные данные
* `./output/` -- артефакты
* `./src/` -- основные скрипты
    * `./src/Converter.py` -- модуль конвертирования входных данных в выходные
    * `./src/Storages.py` -- модуль для парсинга и хранения XML/JSON
* `./tests/` -- юнит-тесты
* `./main.py` -- основной файл для запуска программы

### Запуск
---
В корне проекта открыть консоль и написать:
```
python main.py
```
После выполнения в директории `./output/` появятся артефакты

### Примечания по разработке
Самый непонятный момент для меня - это `./output/res_patched_config.json`. Самый простой способ его генерации - это избежание генерации, что в первую очередь и пришло в голову, но в чём смысл писать метод для простого a = b? Я решил попробовать реализовать это с помощью алгоритма, но я считаю это странным решением, и всё ещё склоняюсь к однострочному методу

В целом, если как-то резюмировать, то задача очень классная и интересная: как только получилось сесть за неё, оторваться смог только после того, как дописал минимально рабочую версию.
